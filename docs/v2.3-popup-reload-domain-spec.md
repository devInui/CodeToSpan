# CodeToSpan v2.3 Popup / Reload / Domain 仕様書

## 目的

この仕様書は、v2.3 の追加修正として確定した popup のリロード挙動、古い設定の検出、ドメイン除外操作、popup / option ページのUIブラッシュアップ、ユーザー向けQ&A作成タスクをまとめるものです。

## 確定仕様

### STOP/RUN 切替時のリロード確認

- STOP/RUN 切替時のリロード挙動を設定できるようにします。
- デフォルトは「リロード前に確認する」です。
- 自動リロード設定が有効な場合、STOP/RUN 切替時に確認せず現在タブをリロードします。
- 自動リロード設定が無効な場合、ブラウザ標準の `confirm()` で確認します。
- 確認文言は次の通りです。
  - `Reload current tab?`
- リロードした場合、リロード完了後に popup の `Outdated Settings Detected.` 状態が最新状態へ更新される必要があります。

### Outdated Settings Detected

- popup の警告文言は次のまま維持します。
  - `! Outdated Settings Detected.`
- popup の横幅は、この文言が1行で収まる幅にします。
- 現在ページが `Language-Based` または `Exclude Domains` によって除外中の場合、通常は `Outdated Settings Detected.` を表示しません。
- ただし、option ページの変更によって現在ページの除外状態が変わった場合は、リロードが必要なため警告を表示します。
  - 除外対象になった
  - 除外対象から外れた

### 拡張機能アイコンのバッジ

- 現在タブにリロードが必要な場合、拡張機能アイコンにバッジを表示します。
- バッジ文字は `R` です。
- バッジ背景色はオレンジです。
- 現在タブがリロード不要になったらバッジを消します。
- バッジ表示の判定は、popup の `Outdated Settings Detected.` と同じリロード要否ロジックに揃えます。

### popup の Show More 領域

- `Options` と `Check Domain` は初期表示では隠します。
- アイコン付きテキストボタン `Show More` を追加します。
- 展開後は `Show Less` に切り替えます。
- 開閉状態は `chrome.storage.local` に保存します。
- 次回 popup を開いたときも前回の開閉状態を復元します。
- 展開時の並び順は次の通りです。
  1. `Options`
  2. `Check Domain`
- `Options` は従来のテキストリンクではなく、ボタン風UIにします。
- `Options` と `Check Domain` の見た目は揃えます。

### popup のドメイン確認

- `Check Domain` を押すと、現在ページの `hostname` を表示します。
- 表示する値は、既存の除外判定と同じ `window.location.hostname` に合わせます。
- `https://`、パス、クエリは含めません。
- コピー機能は追加しません。
- `Check Domain` 後は、hostname と短い `Add` ボタンを表示します。
- hostname がすでに `excludedDomains` に登録済みの場合:
  - ボタンを無効化します。
  - ボタン文言は `Added` にします。
  - アラートは出しません。
- `chrome://` や `about:` など hostname を取得できないページでは:
  - `Domain unavailable` と表示します。
  - `Add` ボタンは表示しません。
- 長い hostname でも popup 全体の横幅を広げません。
- hostname 表示欄だけ横スクロール可能にします。
- `Add` / `Added` ボタンは常に見える位置に固定します。

### popup から Exclude Domains へ追加

- `Add` を押すと、現在ページの hostname を `excludedDomains` に追加します。
- v2.3 では既存のマッチング方式を変更しません。
- 除外判定は引き続き hostname の完全一致です。
- サブドメイン一致やURLパターン対応は v2.3 では実装しません。
- ドメイン追加後、ブラウザ標準の `confirm()` でリロード確認をします。
- 確認文言は次の通りです。
  - `Domain added. Reload current tab?`
- ユーザーがOKした場合のみ現在タブをリロードします。
- キャンセルした場合はリロードせず、リロードが必要な状態として扱います。

### option ページの Exclude Domains UI

- Exclude Domains の削除ボタンは、各ドメイン行の右端ではなく左端に配置します。
- option ページ側のドメイン登録・削除の意味は現状維持です。
- v2.3 ではドメイン照合ルールの拡張は行いません。

## 新しいデザイン案

### popup

- popup はコンパクトな固定幅にします。
- 幅の基準は `! Outdated Settings Detected.` が1行で収まることです。
- 初期表示は重要な操作だけに絞ります。
  - アプリ名
  - RUN/STOP スイッチ
  - 現在状態
  - 必要な場合のみ警告
  - `Show More`
- `Options` と `Check Domain` は `Show More` 展開時のみ表示します。
- 操作ボタンの見た目を揃えます。
  - `Reload`
  - `Show More` / `Show Less`
  - `Options`
  - `Check Domain`
  - `Add` / `Added`
- 装飾は控えめにし、ツールとして使いやすい見た目にします。
- ドメイン表示行は次の構成にします。
  - 左: 横スクロール可能な hostname 表示欄
  - 右: 固定幅の `Add` / `Added` ボタン

### option ページ

- 現在の1ページ構成は維持します。
- セクションのまとまりを見やすくします。
  - Code conversion exclusions
  - Language behavior
  - Translate attributes
  - Exclude Domains
  - Reset
- 各設定項目の余白とラベルの見た目を揃えます。
- Exclude Domains の行は、左に削除ボタン、右にドメイン名を配置します。
- 行の高さを安定させ、リストとして読みやすくします。
- 説明文は補足情報として控えめな見た目にします。
- 英語・日本語の両ロケールで文字がはみ出さないことを確認します。

## ユーザー向けQ&A作成タスク

ユーザー向けのQ&Aドキュメントを作成します。最低限、次の内容を含めます。

- RUN/STOP は何を切り替えるのか
- なぜ現在タブのリロード確認が出るのか
- `Outdated Settings Detected.` は何を意味するのか
- 拡張機能アイコンの `R` バッジは何を意味するのか
- `Language-Based` がONのとき、なぜ処理されないページがあるのか
- `Exclude Domains` はどのように一致判定されるのか
- なぜ `example.com` では `sub.example.com` が除外されないのか
- v2.3 でURLパス単位の除外に対応しない理由
- popup の `Add` は何を追加するのか
- `Domain unavailable` が表示されるのはどのような場合か

## v2.3 では扱わないこと

- サブドメインワイルドカード一致。
- URLパス単位の除外。
- popup のドメインコピー機能。
- ブラウザ標準 `confirm()` を独自確認UIへ置き換えること。

## 追加修正項目

### Check Domain の hostname 取得

- popup の `Check Domain` は、content script が `checkSettings` で返す `hostname` を使って表示します。
- popup 側で `tabs[0].url` から別経路で hostname を作る方式は使いません。
- これにより、除外判定と popup 表示で同じ `window.location.hostname` を使います。
- content script が応答できない場合は、従来どおり `Domain unavailable` を表示します。
- デバッグ用の hostname `console.log()` は削除します。

### popup 操作直後の warning / badge 再判定

- RUN/STOP 切替後に再読み込みをキャンセルした場合、popup を開き直さずに `Outdated Settings Detected.` と `R` バッジを即時更新します。
- 再判定は、現在タブが保持している旧設定と `chrome.storage.sync` の最新設定を比較して行います。
- 除外中ページで再読み込み不要と判定される場合は、popup warning も `R` バッジも表示しません。
- popup 初回表示時と RUN/STOP 直後で、同じリロード要否判定を使います。

### Options 変更後の badge 再判定

- Options 変更後の `R` バッジは、全タブへ即時一括反映せず、アクティブになったタブを対象に再判定します。
- 再判定タイミングは次の2つです。
  1. タブがアクティブになったとき
  2. そのタブの読み込みが完了したとき
- content script が存在しない、または応答できないタブでは、既存の `R` バッジを消します。

### Options ページのフォーム挙動

- Options ページは送信フォームではないため、`<form>` を通常のコンテナへ置き換えます。
- `Add` ボタンと除外ドメイン削除ボタンは `type="button"` を明示します。
- ドメイン登録に成功した場合だけ入力欄を空にします。
- 空入力や重複登録で失敗した場合は、入力欄の値を残します。

### Exclude Domains 削除ボタン UI

- 現在の `X` ボタンは中央揃えを修正します。
- 最終案は `F2` 系を採用します。
- ボタン単体ではなく行全体を hover 時にわずかに持ち上げます。
- 通常時は静かなゴースト角丸ボタンとし、削除アイコンは hover 時に赤へ変化させます。
- 文字列の視覚位置は `translateY(-1.5px)` を採用します。

## 最終手動確認前の実装状況

- `Check Domain` は content script が返す `hostname` を表示する実装に変更済みです。
- RUN/STOP 切替で再読み込みをキャンセルした直後、popup warning と `R` バッジを即時再判定します。
- Options 変更後の `R` バッジは、タブのアクティブ化時と読み込み完了時にアクティブタブだけ再判定します。
- Options ページは送信フォームではなくなり、設定変更で `?excludePre=on` などのクエリがURLに付かない実装です。
- Exclude Domains の Add は、成功時だけ入力欄をクリアします。空入力と重複時は入力欄を残します。
- popup からドメインを追加した後、再読み込みをキャンセルした場合は `R` バッジを表示し、OKした場合はバッジを消してから再読み込みします。
- Exclude Domains の削除ボタンは `F2-1.5` 案で実装済みです。
- 自動テストは 48 件まで追加済みです。
- 残る確認は、実Chromeでのユーザー手動テストと Chrome Web Store 更新資料の実反映です。

## リファクタリング候補

### reload-required 判定の共通化

- 現在、`popup.js` と `background.js` に reload-required 判定のコアロジックが重複しています。
- 片方だけ修正されると、popup warning と `R` バッジの判定が再びずれるリスクがあります。
- Manifest V3 の extension service worker は ES module を公式にサポートしているため、`background.service_worker.type = "module"` と popup の `<script type="module">` を使って共通モジュール化します。
- 共通化対象は、設定差分の判定、ページ適用判定、除外ドメイン変更時の reload 要否判定です。
- 実装時は静的 `import` のみを使い、リモートコードや dynamic import は使いません。
- `src/reloadState.js` に共通判定を切り出し、popup warning と `R` バッジが同じ適用判定を使うようにしました。
